# 问题重定义：搜索 UX / 归档 / 信源（v2.4.5）

## 旧问题（错误）

| 旧问法 | 症状 |
|--------|------|
| 怎么让每次搜索都「更完整」？ | 日常结果又长又噪，链接与摘要缠在一起 |
| 怎么尽量多存档？ | 磁盘噪声、低价值 run 淹没研究档案 |
| 深度研究有没有新引擎？ | 忽略可复现、可引用、可对比 |

## 新问题（正确）

| 新问法 | 对应能力 |
|--------|----------|
| Agent/人怎么**最快核到可点开的信源**？ | `sources[]` + 底部「相关信源」 |
| 什么时候**值得**跨会话保留发现层？ | 研究默认归档；日常 opt-in |
| 结论怎么**挂编号**而不是刷 URL？ | `[n]` 标注 + 底部链接表 |

**一句话**：日常搜索 = 轻 SERP；深度研究 = 可复现证据包。

## MECE 分层

```
查询价值
├─ 日常发现（daily search）
│   ├─ 产出：title + snippet + sources[]
│   ├─ 展示：正文编号，链接沉底
│   └─ 持久化：默认不归档（--archive 才写）
└─ 深度吸收准备（research）
    ├─ 产出：key_findings + citations/sources + gaps
    ├─ 展示：正文 [n]，底部相关信源
    └─ 持久化：默认归档（--no-archive 退出）
```

两层互不重叠：日常不承担档案义务；研究不承担「极简 SERP」义务。

## 量化闸门

| 指标 | 日常搜索 | 深度研究 |
|------|----------|----------|
| 默认归档率 | **0%**（opt-in） | **~100%**（opt-out） |
| 人读输出：正文含完整 URL | 否（沉底） | 否（沉底） |
| JSON：`sources[]` | 必有 | 必有（与 citations 对齐） |
| 单次磁盘写 | 0（无 --archive） | 1 个 run 目录 |
| snippet 作事实引用 | 禁止 | 禁止（须 fetch） |

## 非目标

- 不把日常搜索变成研究报告  
- 不把归档当 cache 淘汰策略  
- 不自动 fetch 正文（发现 ≠ 吸收）  

## 验收

1. `format_text_output` 含 `── 相关信源 ──`  
2. `super_search` JSON 含 `sources`  
3. `research` 无 flag 时写 archive；`--no-archive` 不写  
4. `search` 无 `--archive` 不写
