# 渐进式策略与 token 纪律

本 skill 的核心不是「更快地搜索」，而是「用最少的 token 拿到答案」。
工具输出就是压缩结果，模型不该有探索成本。

## 三层渐进（永远按此顺序）

```
L1 定位      seek.py "词" --count / --filename
             → 输出「文件:命中数」或文件路径列表，每行 < 80 字符
             ↓ 从中挑出最相关的 1-3 个文件
L2 上下文    seek.py "词" --context 2 --path <该文件所在目录>
             → 输出「路径:行号:命中行 ± 2 行」
             ↓ 确定要精读的段落
L3 精读      read_file 该文件，用行号偏移局部读取
```

任何一步已经能回答用户，就停。不要为完整性多搜。

## 搜索范围扩大的顺序（先窄后宽）

1. 当前目录 + 默认排除（最常命中）
2. `--path` 扩大到知识域（~/notes、~/Documents 等，见 domains.yaml）
3. `--spotlight` 全盘兜底

禁止跳级：用户问「找代码里某个函数」却直接 mdfind 全盘，浪费且不准。

## 输出量控制

| 手段 | 效果 |
|------|------|
| `--max 20` | 截断结果数，防止刷屏 |
| `--count` | 只报分布，不报内容 |
| `--type py,ts` | 只扫目标类型 |
| `--context 0`（默认） | 不输出上下文行 |
| `-l` 手动模式 | 只列文件名 |

## 常见失败与换词策略

| 现象 | 处理 |
|------|------|
| 无匹配 | 换同义词/拆词/去掉修饰词，重试 1 次后换工具 |
| 命中过多 | 加 `--type` / `--max` / 更具体的关键词（加引号做短语匹配） |
| 结果太泛 | 指定目录缩小范围 |
| 搜代码但命中注释/文档 | 换更精确的符号名或结构模式 |
| Spotlight 搜不到 | 确认目录已索引；退回 rg + 明确 --path |

## 与 Argo 的分工

- 用户要「网上查」→ argo（联网）
- 用户要「本地找/搜我的文件」→ local-seek
- 混合需求（如「查网上的同时翻本地笔记」）→ 并行调用，互不干扰
